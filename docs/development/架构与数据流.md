# 架构与数据流

听笺基于 SwiftPM 构建（零第三方依赖，最低系统要求 macOS 26.0），核心模块为 `TingjianCore`（无 UI 依赖）、原生应用 `Tingjian` 与隔离回归工具 `tingjian-check`。

- **工作区与状态分层。** SwiftUI 视图按页面边界拆分为 7 文件（`ContentView`、`SidebarView`、`RecordingView`、`DocumentDetailView`、`PlaybackControlBand`、`DirectoryAndAudioViews`、`WorkspaceSheets`），`AppModel` 按主状态、资料库、文稿播放、录音会话与文字纠正拆分为 5 文件；纯路径重映射与可见块高亮逻辑抽离至 `TingjianCore/WorkspaceState.swift`（`WorkspacePathMapper`、`DocumentHighlightResolver`）。侧栏展示资料库与持久化录音草稿，支持「最新录音优先 / 按名称升序」排序，并后台轻量探测一级目录的录音标识；`ProjectLibrary` 串行执行改名（含 APFS 仅改大小写）、移动、废纸篓与同目录链接同步。
- **录音采集、合盖拦截与弱音增强。** `Recorder` 拆分为主控制（`Recorder.swift`）、保存与恢复（`Recorder+Recovery.swift`）和引擎/设备监听（`Recorder+Engine.swift`）3 文件。真实麦克风路径在开始、继续、换麦及睡眠唤醒重建输入前经 `HardwareInputGuard` 查询 IOKit（`AppleClamshellState`）与 CoreAudio（`kAudioDevicePropertyTransportType`），确认合盖且指向内置麦时拦截（未知环境降级放行）。`AudioPipeline` 采用读写分离：原始采集直接写入本机未压缩 `audio.caf`（0 DSP 污染），转写分支经 `SpeechEnhancer` 实时预处理后送入 `SpeechAnalyzer / SpeechTranscriber`；离线补转 `Retranscriber` 在内存中复用同套 `SpeechEnhancer` 预处理，不改原音频。
- **本地落盘与崩溃恢复。** 录音中持续将确认事件追加至 `transcript.jsonl`，将未最终确认的实时草稿按节流原子写入 `volatile.json`（随 `onFinal`、引擎失败或会话结束清空），并维护 `session.json`（固定启动时的保存目标、草稿关联、课程名与说明）。异常中断重启后由 `Recorder.recover(dir:)` 逐份扫描恢复，保留音频、已确认文字、末段实时草稿及后续时长缺口。结束时并行收尾识别与导出 AAC M4A（不可用时保留 CAF），防休眠活动断言延后至导出与交付收尾完成后释放。
- **原子交付。** 普通录音在目标父目录暂存后以同卷 `renamex_np` 整目录发布；已绑定占位草稿经 `RecordingPlacement` 同卷暂存写入原占位目录（判空与交付自动忽略 `.DS_Store`），发布清单与回执标识支持中断后接续。本地文件发布与 iCloud 跨设备同步分别验收。
- **文稿解析、回听与查找。** 后台通过 `MarkdownDoc.parseDocument` 结构化解析标题、元信息、转写状态、`## 说明`、`> ⚠` 缺口块与校正版来源链接（兼容普通 Markdown）；`PlaybackModel` 基于 `AVPlayer` 提供 `1.0x–2.0x` 保音高倍速、`±5s / ±10s` 步进与单标签独立进度；`TranscriptLocator` 负责播放当前段二分高亮（跳过已隐藏空锚点）与带时间戳转写稿的 `⌘F` 页内关键词匹配。
- **文字纠正。** `TextCorrector` 先提取全文语境（前导信息剔除 `## 说明` 与库外父目录名），再按连续段落分批发送至 OpenAI 兼容网关，严格校验返回段落 ID 与顺序，截断时对半拆分重试，写出前重读原稿防外部冲突，关联原时间戳另存 `_校正版.md`。轻度清理与全面书面化各自缓存结果；API 密钥按规范化网关地址隔离存入系统钥匙串。
