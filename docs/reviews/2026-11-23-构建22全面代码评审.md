## 3. B 类：复杂 / 中长期剩余问题（按 P0 / P1 / P2 排序）

### P0（高优先：直接决定课堂核心可用性）

1. **极端组合弱音召回瓶颈（跨会话状态滞留 + 低 SNR/低通实质退化）**
   - **实测证据与根因线索**：
     - 第一讲稿 `combined-weak.caf` 在连续 5 组与独立单跑中 **SHA-256 位级一致**（`9707863587bcf0bf00fd517ca6e4938df7447004438e52769d47232fd207f5c4`）、送入识别器均 353 包，但连续 5 组第 5 会话掉至 **10/15（66.7%，CER 16.3%）FAIL**（构建 23 复测一致），独立进程单跑 ×2 稳定恢复为 **12/15（80.0%，CER 13.0%）PASS**。[Engine.swift](../../Sources/TingjianCore/Engine.swift) 使用 `modelRetention: .lingering`，同进程连续分析存在跨会话识别状态影响（如噪声底估、VAD 适配或 XPC 资源节流）。
     - 第二讲稿 `--weak-voice-holdout`（缓存系统）在构建 23 已将前 4 组门禁校准为 `>= 80% 召回且 CER <= 8%`（对应 0 dB 合成基线 12/15 = 80.0%、CER 3.7%），构建 23 前 4 组全部通过；但组合弱音严格保留 80% 门禁不放宽，在连续 5 组与独立单跑中均为 **7/15（46.7%，CER 18.5%）FAIL**，证明极低 SNR + 低沉低通本身仍存在实质准确率瓶颈，并非仅由连续分析导致。
     - [SpeechEnhancer.swift](../../Sources/TingjianCore/SpeechEnhancer.swift) 当前四阶 105 Hz HPF 对降调 -3 半音的低沉男声基频（~85–110 Hz）有切损，280 Hz 侧链与 -52 dBFS 门限在 `-20 dB + LP 1100 Hz` 组合下易使轻音节门限回落。
   - **推进顺序**：① 对照 `.lingering` 与默认保留策略在跨会话下的表现；② 补采真实课堂低沉/远场样本做对照；③ 仅在具备跨样本复现依据后再微调 HPF/侧链/AGC 参数。

2. **真实麦克风、课堂长时识别、桌面强退恢复与资源占用验收缺失**
   - **现状**：目前 30 分钟长测均基于 `MockEngine`；`--real5`（真实 5 分钟）未执行；桌面端 GUI 强退恢复因自动化会话受 macOS 辅助功能 TCC `-1728` 拦截仍处于未验状态；尚无真实 `SpeechAnalyzer` 长时（30–90 分钟）CPU、内存、热节流、`convQueue`/`ReplayRing` 积压及真实课堂（远场/回响/AirPods/内置麦/多设备热拔插）与无中文模型设备下载补转的实测数据。
   - **推进顺序**：先在具备权限的本机桌面完成 `--real5` 与桌面 GUI 强退恢复复验，再按课堂场景记录真实设备长时指标。
