## 一、核心结论与总体评分

听笺当前是一个**工程底盘极扎实、数据安全观极克制，但“录后消费（阅读、回听、校对）与信息架构”尚未完全跟上“录中可靠性”**的 macOS 原生工具。

| 评审维度 | 当前成熟度 | 一句话判断 |
| --- | --- | --- |
| **定位与差异化壁垒** | ★★★★★ | 「原生离线实时转写 + 无数据库纯文件/Obsidian 协同 + 故障保音频 + 可选自带网关连续纠正」切口精准、不可替代性强。 |
| **数据安全与异常兜底** | ★★★★☆ | 读写分离保原音、逐段 JSONL 落盘、原子发布与防覆盖理念过硬；主要短板在未实测真机长时、合盖内置麦拦截缺失与本地备份容量不可见。 |
| **课中录制体验** | ★★★★☆ | 构建 22–23 将合成首字延迟从 12.2 秒压至 1.1 秒，暂停/换麦/退应用保护较完善；缺课中改名、误触结束防线与重点打点。 |
| **课后阅读与回听复习** | ★★☆☆☆ | **当前最大产品短板**：正文渲染吞掉了元数据/缺口警示/校正版标识，缺页内查找（⌘F）、缺倍速/快进退/空格播停/当前句高亮，重转写与纠正入口过深。 |
| **信息架构与心智一致性** | ★★★☆☆ | 命名展示五处割裂、未展开目录不显示录音标记、列表按旧到新升序、文件标签栏与非文件视图顶栏冲突、设置页暴露部分个人/底层概念。 |
| **稳定版/私测发布就绪度** | ★★★☆☆ | **个人主力**：完成最小桌面+真实麦克风验证后即可替换稳定版；**对外私测**：需先解决默认网关/路径个人化、ad-hoc 签名门槛与合盖误录提示。 |

**三个最值得立刻关注的产品级发现（此前代码评审未覆盖）：**

1. **文稿阅读页静默吞掉了所有「转写不完整」缺口警示与文稿元信息（P0）**：Markdown 落盘时忠实写入了 `# 标题`、转写状态（完成/部分完成/失败）、`## 说明`（含换麦/异常记录）以及 `> ⚠ [HH:MM:SS]–[HH:MM:SS] 此区间转写不完整`（[Export.swift](../../Sources/TingjianCore/Export.swift#L70-L87)），校正版头部还写了模型名与 `[[原始转写]]` 链接（[LLM.swift](../../Sources/TingjianCore/LLM.swift#L598-L599)）。但 `DocumentDetail` 在存在时间戳段落时**只渲染 `parseSegments` 解析出的 `[HH:MM:SS]` 行**（[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1442-L1469)、[AppModel.swift](../../Sources/Tingjian/AppModel.swift#L1313-L1315)），导致用户打开“部分完成”的文稿时**完全看不到缺口、状态和换麦说明**，打开校正版时**既看不到这是校正版也无法点回原稿**；同时，LLM 删空的纯语气词段被渲染为孤零零的空时间戳行（[LLM.swift](../../Sources/TingjianCore/LLM.swift#L593)）。
2. **核心课后功能（「纠正文本」与「重新转写」）入口严重隐蔽（P1）**：打开文稿后，主区没有任何显眼按钮触发「纠正文本」，必须点右上角 `…` 菜单（[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L298-L306)）；而「重新转写」被完全埋在「设置 → 保存与恢复 → 选择录音…」（[SettingsView.swift](../../Sources/Tingjian/SettingsView.swift#L102-L110)），在音频页、文稿页与侧栏右键菜单中均无上下文入口。
3. **复习与多学期规模增长下的效率断层（P1）**：播放器只有播停与进度条，无倍速、无快进退、无空格快捷键、无播放段落高亮、点击时间戳不自动播放（[PlaybackModel.swift](../../Sources/Tingjian/PlaybackModel.swift#L109-L146)、[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1743-L1795)）；全应用无页内搜索（⌘F）或侧栏筛选；侧栏目录按名称**升序**排列（[ProjectLibrary.swift](../../Sources/TingjianCore/ProjectLibrary.swift#L128-L131)），随着学期推进，最新录制的课程会不断沉到列表最底端。

## 二、产品定位、核心价值与轻量竞品对照

### 2.1 核心价值闭环审视

听笺试图解决的是一个非常具体的垂直痛点：**在 Mac 上持续录制 45–90 分钟中文课程，课中低干扰实时看到文字，课后零导入直接变成 Obsidian 可读、可回听、可按需 LLM 精修的本地 Markdown + M4A 资产，且绝不因识别失败或闪退丢掉音频。**

这条闭环里，听笺最强的工程护城河已经建立：
- **纯文件系统即资料库**：零数据库锁定，直接读写本地/iCloud 文件夹，配合 `![[音频]]` 双向链接融入 Obsidian。
- **不破坏原件的派生哲学**：原始音频（写入前不经 DSP 污染）、原始转写、`_校正版.md`、`_重转写.md` 严格分离，任何写入或改名出错均有回滚或局部保底。
- **可控的连续段落 LLM 纠正**：自带网关/本地模型、按上下文连续清理口语重复同时严格保住逐段时间戳锚点。

### 2.2 轻量竞品定位对照

| 方案 | 实时中文转写 | 音频-文稿时间轴回听 | Obsidian/纯文件原生度 | 隐私与离线可控 | 相对听笺的胜出点 | 相对听笺的明显短板 |
| --- | --- | --- | --- | --- | --- | --- |
| **Apple 语音备忘录** | 有（系统级） | 弱（无独立 Markdown 资产） | 极差（封闭库） | 高 | 系统级合盖/休眠/音频路由集成、iCloud 同步成熟 | 无法融入 Obsidian 知识库、无课程项目管理、无 LLM 校对 |
| **MacWhisper** | 有（偏离线模型导入/听写） | 中 | 弱（需手动导出 Markdown） | 高 | Whisper 生态多语种/专业术语强、支持批量导入外部音视频 | 偏通用转写工具，非“课堂工作区 + Obsidian 资料库”一体化流 |
| **飞书妙记 / 通义听悟** | 有（云端） | 强（高亮跟随、倍速、搜索、总结、说话人区分） | 差（云端封闭、需导出） | 低（录音全上传云端） | **课后复习体验极强**（搜索、倍速、当前句高亮、大纲、重点打点） | 强联网、隐私与课堂录音外传顾虑、受平台订阅与导出限制 |
| **Obsidian 录音插件** | 弱/需第三方 API | 弱 | 高 | 取决于插件 | 直接在笔记正文内嵌录制 | 长时间录制稳定性差、无故障恢复与实时弱音流式转写 |
| **听笺（当前）** | 有（Apple 原生离线 + 弱音增强） | **基础可用，体验单薄** | **极高** | **极高（音频永不离机）** | **原生稳定 + 零导入融入 Obsidian + 可控本地/自带网关校对** | 复习交互单薄（无搜索/倍速/高亮）、信息架构偏工程化、私测门槛偏高 |

**定位校准结论**：听笺不需要变成“本地版飞书妙记”（不要引入数据库、账号体系、云同步服务或臃肿的富文本编辑器），但必须补齐**「录后高效阅读与回听」**这一半闭环——否则用户录完后在听笺里既找不着重点、又不好倍速回听、还得切去 Obsidian 才能看到缺口提示和原稿链接，听笺的主窗口工作区就会退化成一个昂贵的“录音按钮”。

## 三、端到端课堂全旅程走查（6 阶段）

### 阶段 1：首次上手与冷启动

- **源码位置**：[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L2238-L2277)（`InitialSetupView`）、[Support.swift](../../Sources/TingjianCore/Support.swift#L34-L37)、[GatewayPreferences.swift](../../Sources/TingjianCore/GatewayPreferences.swift#L16-L30)、[AppModel.swift](../../Sources/Tingjian/AppModel.swift#L276-L303)。
- **做得好的地方**：首启引导简洁（475px 弹窗），把保存位置、中文识别模型状态和是否启用文字纠正三件核心前置事放进一屏，且旧版本升级能保留原配置。
- **产品摩擦点**：
  1. **默认保存路径强假设用户装了 iCloud Obsidian**：`Paths.defaultSaveRoot` 写死为 `~/Library/Mobile Documents/iCloud~md~obsidian/Documents/听笺`。对于未开启 iCloud Obsidian 的私测用户，直接点「完成设置」会在 `~/Library/Mobile Documents/` 下静默建出一个普通本地目录，既不会同步到 iCloud，也极难在 Finder 中找到。
  2. **默认文字纠正网关带有强个人环境烙印**：新用户勾选「启用文字纠正」后，默认网关指向本机 `Magpie`（`http://127.0.0.1:3425/v1`）、默认模型为 `sdu/ByteDance-volcengine/DeepSeek-V4.1-Flash`。对外部私测用户而言，点「完成设置」后首次纠正必然因连不上本机 3425 端口而失败。
  3. **首启缺少麦克风权限与设备预检说明**：首启页检查了语音模型，但完全没有展示当前将使用的麦克风，用户直到真正上课按下「开始录音」才首次触发系统权限弹窗或发现设备异常。

### 阶段 2：课前准备与组织

- **源码位置**：[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L527-L747)、[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1100-L1230)、[AppModel.swift](../../Sources/Tingjian/AppModel.swift#L819-L942)、[ProjectLibrary.swift](../../Sources/TingjianCore/ProjectLibrary.swift#L135-L170)。
- **做得好的地方**：录音空白页布局清爽，支持 `⌘N` 快速开草稿、`⌘↩` 一键开录、明确分离“浏览目录”和“录音目标”，防止误把录音存进上次随手点开的文件夹。
- **产品摩擦点**：
  1. **三种决定保存位置的机制叠加，概念偏重**：用户可以 ① 直接录进根目录、② 在某项目点「在此录音」（设置 `draft.project`）、③ 从「暂存」拖草稿到某项目或点「选择保存位置…」（立刻在磁盘创建含隐藏标记的空目录 `RecordingPlacement`）。② 和 ③ 界面外观几乎一样，但 ③ 会在磁盘留下空文件夹，且**关闭草稿后空文件夹不会被清理**（[使用指南.md](../guides/使用指南.md#L21)），容易在用户的 Obsidian 资料库里制造“幽灵空目录”。
  2. **暂存区为空时仍残留孤立标题**：关闭全部草稿后，`SidebarPanel` 仍固定渲染「暂存」标题（[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L565-L573)），下方空无一物。
  3. **课程名与最终落盘命名预期割裂（用户已反馈）**：用户输入课程名「测试」，普通录音落地为 `2026-11-24_14-30-00_测试/` 文件夹 + 同名 `.m4a`/`.md`；拖放占位草稿落地为 `测试/` 文件夹 + 内部带日期前缀的 `2026-11-24_14-30-00_测试.md`。用户视角看到的规则前后矛盾。
  4. **合盖 + 内置麦克风无事前拦截（用户已反馈）**：Apple 芯片 Mac 合盖硬件断开内置麦克风，但目前仍允许开始录制并产出静音/极弱底噪文件。

### 阶段 3：课中 45–90 分钟持续录制

- **源码位置**：[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1021-L1098)、[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1678-L1740)、[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1865-L1991)、[TingjianApp.swift](../../Sources/Tingjian/TingjianApp.swift#L97-L140)。
- **做得好的地方**：实时文本 16pt 大字号 + 左侧等宽时间戳 + 实时蓝点行观感很舒服；向上回看历史时自动停滚并浮出「回到最新」按钮；支持底栏临时换麦、设备拔出自动暂停保护、录中退出强弹窗拦截。
- **产品摩擦点**：
  1. **开录后无法修改或补填课程名**：点击开始录音后，`CurrentRecordingView` 切到 `transcript` 视图，课程名输入框消失（[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1040-L1044)）。课上匆忙按 `⌘↩` 先录起来、想等两分钟再补课程名是极高频场景，目前只能等整节课录完保存后再去重命名文件夹并勾前缀同步。
  2. **「结束」按钮与 `⌘⇧S` 快捷键缺少误触保护**：`ControlBand` 的「结束」直接触发 `rec.stop()`，且快捷键为 `⌘⇧S`（[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1729-L1740)）。在 macOS 习惯里 `⌘⇧S` 通常是「另存为」或「保存」，课堂录到 40 分钟时若误触，会直接不可逆地终结本次会话并进入收尾，无法继续接录到同一份文稿里。
  3. **缺少「课中打点 / 重点标记」**：45–90 分钟的课，最需要的是老师讲到重点/作业/考点时按一下快捷键记一个时间标记（哪怕只是一个带可选短备注的书签行写入 Markdown），课后直达回听。当前只能靠肉眼在一万字里翻。
  4. **无持续静音 / 弱音无采集提醒**：除左下角小电平条外，若麦克风被静音开关关掉、或合盖/选错虚拟声卡导致连续 30–60 秒无有效人声电平，界面没有任何温和提示，容易一整节课录下来全是静音才追悔莫及。
  5. **录音中顶栏失去当前课程上下文**：只要 `openTabs` 里之前打开过哪怕一个旧文件，录音页顶栏就会被 `tabBar` 占据，当前录音的课程名称完全不显示（[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L187-L195)）。

### 阶段 4：课后交付与异常兜底

- **源码位置**：[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L404-L433)、[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1798-L1847)、[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1993-L2088)、[AppModel.swift](../../Sources/Tingjian/AppModel.swift#L464-L481)。
- **做得好的地方**：交付成功后自动移除草稿并直接打开新生成的 Markdown；目标写入失败时顶部横幅、底部控制带、状态详情三级兜底清晰，支持重试保存与更换保存位置；异常中断重启后可发现并恢复。
- **产品摩擦点**：
  1. **「部分完成 / 失败」会话交付后缺乏显性行动闭环**：当录音因缺模型或识别故障以「部分完成 / 失败」交付并自动跳到 `DocumentDetail` 后，页面上既不显示转写状态横幅，也没有一键「重新转写此录音」按钮；用户很容易以为转写完整，或者找不到补转入口。
  2. **多份未完成录音只能盲目恢复第一份**：`IssuesPopover` 的恢复按钮固定调用 `model.recoverFirst()`（[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L2080)），若本地存在 2 份以上未完成会话，弹窗只列出第一份路径，未列出清单供用户分别查看或选择恢复顺序。
  3. **本地恢复备份只报份数、不报磁盘占用**：`SettingsView` 的「本地备份」仅显示 `X 份已成功交付的本地备份`（[SettingsView.swift](../../Sources/Tingjian/SettingsView.swift#L360-L364)）。由于本地保留未压缩 CAF 录音，10 节 90 分钟课程即可轻松占用数 GB 空间，用户看不到体积也缺乏“保留最近 N 天/自动提醒清理”机制。

### 阶段 5：课后阅读、回听与复习

- **源码位置**：[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1403-L1644)、[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1742-L1796)、[PlaybackModel.swift](../../Sources/Tingjian/PlaybackModel.swift)。
- **做得好的地方**：16pt 行距宽松舒适，阅读宽度限制在 `960pt` 内，保留每标签页独立滚动位置和每音频独立播放进度；缺失音频时降级优雅不阻断阅读。
- **产品摩擦点（全产品最集中的体验短板）**：
  1. **正文解析丢弃了元数据、说明与「转写不完整」缺口块**：如前所述，`DocumentDetail` 在 `doc.lines` 非空时仅显示 `[HH:MM:SS]` 行。原稿的录制日期、时长、转写状态、换麦记录、缺口警告（`> ⚠ ...`）以及校正版的来源标识（`原始转写:[[...]]`）全部不可见，藏在文末折叠的「查看原文」里。
  2. **校正版空段落渲染为空白时间戳行**：LLM 删除语气词或跨段重复后留下的纯 `[HH:MM:SS]` 锚点行，在界面中直接渲染为“左侧蓝色时间 + 右侧完全空白”，破坏阅读连续性。
  3. **播放回听能力过于基础**：
     - 缺**倍速播放**（1.0x / 1.25x / 1.5x / 2.0x —— 复习课堂录音刚需）；
     - 缺**快退/快进**（如 -5 秒 / +10 秒按钮与快捷键）；
     - 缺**空格键播放/暂停**全局（非输入态）控制；
     - **点击时间戳仅定位不播放**（[AppModel.swift](../../Sources/Tingjian/AppModel.swift#L1392-L1410)）：用户想听某句话时，点完时间戳还要再把鼠标移到底部点播放键，打断阅读流；
     - 播放音频时**不自动高亮当前对应段落**，也不支持开关“播放跟随滚动”。
  4. **无页内查找（⌘F）与资料库搜索**：一节课万余字无法按关键词定位句子，几十节课后无法按课程名或内容快速过滤侧栏。
  5. **无原稿与校正版快捷切换**：生成校正版后，两个 `.md` 变成同目录下两个普通平级文件，没有顶部「原稿 / 校正版」切换条，校正版里也没有按钮跳回原稿。
  6. **只读文稿不支持轻量标注/编辑跳转**：听笺刻意不做编辑器完全合理，但至少在阅读页应提供顺手的「在默认应用（Obsidian/系统编辑器）中打开」入口，而不是只有「在 Finder 中显示」。

### 阶段 6：AI 纠正、重转写与 Obsidian 协同

- **源码位置**：[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L298-L320)、[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1506-L1532)、[SettingsView.swift](../../Sources/Tingjian/SettingsView.swift#L102-L234)、[AppModel.swift](../../Sources/Tingjian/AppModel.swift#L1578-L1734)、[LLM.swift](../../Sources/TingjianCore/LLM.swift)。
- **做得好的地方**：分块上下文连贯纠正 + JSON 结构严格校验 + 原稿变更冲突保护 + 取消安全 + 本机块缓存 + 数据出境范围透明披露，工程和隐私诚实度远高于同类工具。
- **产品摩擦点**：
  1. **「纠正文本」藏在 `…` 菜单里，且开关关闭时体验别扭**：打开文稿后主区看不到“纠正文本”入口；若用户未开「启用文字纠正」，点 `…` 里的「纠正文本」竟然还能点（因为禁用条件未检查 `llmEnabled`，[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L305)），点完立刻弹一条失败提示「文字纠正已关闭。可在『设置 → 文字纠正』中启用」（[AppModel.swift](../../Sources/Tingjian/AppModel.swift#L1604-L1606)），而不是直接提供前往设置的按钮。
  2. **纠正结果与用量反馈不连贯**：若纠正期间用户在看该原稿，完成后自动跳到校正版，此时挂在原稿 URL 上的 `correctionUsage`（token 用量与缓存命中）随之消失；若用户切去看了别的文件再回来，原稿顶部的 `已生成 xxx_校正版.md` 不可点击打开。
  3. **「重新转写」入口错位**：重转写是对一份已有音频的动作，却只能从「设置 → 保存与恢复」里打开文件选择器触发，无法直接在 `AudioDetail`、`DocumentDetail` 或侧栏右键点击音频/部分完成文稿执行；且 `Retranscriber.writeMarkdown` 把标题写死为 `# 重新转写:<base>`、状态硬编码 `.completed`（[Retranscribe.swift](../../Sources/TingjianCore/Retranscribe.swift#L53-L55)），即便音频全静音产出 0 段也会标成“完成”。
  4. **Obsidian 长期协同的元数据友好度**：目前 Markdown 头部使用无序列表 `- 录制日期:...` 而非标准 YAML Frontmatter（`---`），在 Obsidian 中较难直接用于属性视图、Bases 或 Dataview 按课程/日期/状态汇总（若未来支持，须保持对旧格式解析 100% 兼容）。

### 4.2 其他架构与交互不一致清单

1. **侧栏录音标记“展开前隐身”**：`loadChildren` 为性能传 `classifyDirectories: false`（[AppModel.swift](../../Sources/Tingjian/AppModel.swift#L514)），而 `isRecordingDirectory` 仅查 `childrenByDirectory` 缓存（[AppModel.swift](../../Sources/Tingjian/AppModel.swift#L536-L538)）。结果所有未展开过的录音文件夹在侧栏和父目录详情页里都显示为普通文件夹，只有展开一次后才会突然亮出录音图标和红点。
2. **排序策略不利于课堂时间线**：[ProjectLibrary.swift](../../Sources/TingjianCore/ProjectLibrary.swift#L128-L131) 固定按名称升序，导致带日期前缀的录音目录按**从最旧到最新**排列，最新课程沉底；且没有排序切换选项。
3. **顶栏上下文切换冲突**：[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L186-L195) 用 `if !model.openTabs.isEmpty` 互斥显示 `tabBar` 与 `contextTitle`。一旦有打开的文件标签，切回文件夹、草稿或录音页时顶栏既不显示当前标题，也没有高亮标签，产生“迷航感”。
4. **「新建项目」按钮存在重复与禁用条件不一致**：
   - 顶部菜单「资料库 → 新建项目…」（[TingjianApp.swift](../../Sources/Tingjian/TingjianApp.swift#L25-L27)）在 `recorder.isActive` 时禁用；
   - 侧栏顶部的 `+` 新建项目按钮（[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L545-L552)）和 `DirectoryDetail` 的「新建项目…」（[ContentView.swift](../../Sources/Tingjian/ContentView.swift#L1306)）在录音中却**未禁用**。
5. **侧栏删除/改名/移动右键菜单在各入口略微错位**：
   - `SidebarPanel` 工具栏的「新建项目」提示“在当前文件夹新建项目”，但当用户在录音页/草稿页点它时，`currentDirectory` 回落到 `saveRoot`（[AppModel.swift](../../Sources/Tingjian/AppModel.swift#L489)），容易误以为会建在上次浏览的课程目录里。
   - `DirectoryRow` 右键菜单缺少「复制路径」和目录专属的「在此录音 / 在此新建项目…」（对比 `SidebarRow` 和 `selectedItemMenu`）。
6. **主题文档与实际视觉脱节**：[使用指南.md](../guides/使用指南.md#L51) 仍描述「浅色为暖白纸感，深色为墨绿纸面」，而 [Theme.swift](../../Sources/Tingjian/Theme.swift#L6-L18) 早已演进为纯白（`#FFFFFF`）/ 深灰（`#1C1D1F`）+ 蓝色强调（`#3567B7` / `#8AB4F8`）。

## 六、发布就绪度评估（构建 23 → 稳定版 / 私测门禁）

### 6.1 构建 23 是否建议晋升为稳定版 `/Applications/听笺.app`？

**结论：面向你个人主力使用，条件性建议晋升（完成下述 4 项最小手动验收后即可替换构建 21）；但面向外部同学私测，暂不建议直接分发当前构建 23。**

**晋升个人稳定版前的理由与最小门禁：**
- **明显收益**：相对构建 21，构建 22–23 将合成首字延迟从 12.2 秒降至 1.1 秒，修复了弱音中断/尾帧丢失、0 字失败误标、空目录泄漏、重命名刷新根因与全部编译告警，且原始音频 0 污染（`ΔRMS = 0.00 dB`），整体显著优于构建 21。
- **晋升前必须补齐的 4 项最小手动验收**（来自 [当前版本与验收状态](../project/当前版本与验收状态.md#L48-L54) 中尚未由真机验证的项）：
  1. **真实麦克风弱音/低音 5–10 分钟试录**：对比构建 21 与构建 23 在真实 MacBook 麦克风及常用耳机下的实时出字延迟、漏识与回听音质；
  2. **构建 23 新增 UI 修复桌面复验**：隔离资料库下实测「重命名 + 同步前缀刷新」「设置页重新转写进度与防重入」「录音中顶栏菜单置灰」；
  3. **桌面强退恢复手动复验**：隔离资料库下录制约 30 秒后 `kill -9` 强退再重启，确认恢复并交付完整音频与文稿；
  4. **长时真实识别试跑（`--real5` 或一节真实课堂）**：观察真实 `SpeechAnalyzer` 运行时的 CPU、内存与发热量。

### 6.2 面向外部小范围私测的额外阻塞项

若计划把应用包发给少数 macOS（需 macOS 26 Tahoe，`LSMinimumSystemVersion = 26.0`，[build_app.sh](../../scripts/build_app.sh#L44)）+ Obsidian 同学私测，当前还有 4 个硬门槛需要先解：
1. **默认路径与默认网关去个人化**：首次启动若未检测到 iCloud Obsidian 目录，默认路径应回落到 `~/Documents/听笺` 并提示可选 Obsidian 目录；首次启用文字纠正默认应选「DeepSeek 官方」或未选态，而非本机 `Magpie` 与 `sdu/...` 模型 ID。
2. **合盖 + 内置麦克风防呆拦截**：避免私测用户合盖接显示器录完一小时才发现全静音。
3. **文稿阅读页补回缺口与转写状态展示**：避免私测用户把“部分完成”的文稿误判为完整记录。
4. **分发签名预期管理**：当前为本机 ad-hoc 签名（[build_app.sh](../../scripts/build_app.sh#L59)），发给他人会触发 macOS Gatekeeper 拦截，私测说明需明确提供源码构建方式或签名放行指引（长期公开分发则需 Apple Developer ID + 公证）。

### Non-Goals · 明确不做清单（守住听笺产品基因）

为防止产品膨胀、破坏“轻量原生 + 文件即资料库”的核心优势，建议明确拒绝以下方向：
1. **不做应用内富文本/双向链接笔记编辑器**：正文编辑、知识图谱与双链整理交给 Obsidian，听笺只把“采集 → 转写 → 校对 → 回听”做到极致。
2. **不引入 SQLite/CoreData 数据库来接管资料库**：资料库必须永远 100% 镜像磁盘文件夹，用户随时可在 Finder/Obsidian 里自由移动、备份、版本控制。
3. **不做自建云同步、账号登录或托管 AI 计费**：继续走本地文件 + 用户自带 iCloud/同步盘 + 用户自带网关/密钥，零运营成本且隐私边界绝对干净。
4. **不引入本地大型开源语音模型（如捆绑数 GB Whisper 权重）**：继续依托 Apple 原生 `SpeechAnalyzer` 保持包体极小、能耗低与零外部依赖，把算法投入集中在音频前端调理与流式工程优化。
5. **不做复杂说话人分离 / 多人会议纪要 / 任务看板**：聚焦中文课堂与个人长语音记录场景，避免为了通用会议软件的功能堆砌牺牲启动速度和界面克制感。
