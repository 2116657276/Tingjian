## 两个视角的结论

**日常用户。** 听笺的核心价值是录音、转写和播放共用一套时间轴，产物能直接在 Obsidian 中使用。先修复 Obsidian 与听笺交替操作时的标签陈旧和路径冲突，再统一各入口对「一份录音」的移动语义。录音交付失败后，用户应能从清楚的位置重试，并且最后只看到一份完整成果。浏览规模增加时，优先改善大目录的响应和长文稿播放的连续性。

**macOS 应用架构师。** 保留 SwiftUI、单个 AVPlayer、直接映射磁盘的资料库，以及音频先落本地、识别故障时继续录音的架构。目前的主要边界在路径身份和文件提交的一致性、MainActor 上剩余的同步 I/O、以及高频播放器与录音状态被大范围视图订阅。优先收敛这几条链路，按测量结果决定是否需要更大的拆分。

## 已验证的问题与建议

这里的「复现」指执行当前源码得到可观察结果。成本为单人粗估，含针对性回归，适用于本项目当前结构。

| **P1 · 外部移走文件后复用原文件名可崩溃** | 打开 A.md、B.md 并保留两个滚动位置，在应用外移走 A.md，再在听笺中把 B.md 改为 A.md。隔离进程以 duplicate key 错误退出。改名已落盘，两份内容仍在，但应用会中断，重启后可能难以判断刚才的操作是否成功。多个缓存用 URL 作键，路径重映射时旧目标与新目标折叠到同一个键。 [AppModel.swift](../../Sources/Tingjian/AppModel.swift) · `renameEntry` / `remapPaths` | **约 1–2 天。** 先处理目标路径的失效状态，显式合并或淘汰冲突缓存，并同步展开状态、选中项和标签。在测试里验证磁盘和界面状态一起收敛。先保留 URL 键；只有在要求「外部任意改名后仍自动跟踪同一文件」时再引入稳定文件身份。 |
| **P2 · 交付失败留下半份录音，重试新增第二份目录** | 隔离样本让音频复制成功、文稿源读取失败。目标下留下只含音频的目录，重试后又生成 `demo_2`。遇到故障时可能在 Obsidian 看到两个项目，并误打开缺文稿的一份。录音源仍在本地可恢复。 [Export.swift](../../Sources/TingjianCore/Export.swift) · `Deliverer.deliver` / `copyVerified` | **约 2–4 天。** 在目标父目录以隐藏暂存目录写齐、校验两份文件，再发布完整目录。失败时按一次交付的身份回收或复用暂存，兼顾重名和崩溃恢复。整目录发布能改善本机可见性，iCloud 多设备同步顺序仍需实测。 |
| **P2 · 外部编辑后切回原标签仍显示旧文稿** | 隔离测试中，外部覆盖文稿后刷新项目树、切走再打开，仍显示旧内容。点击「刷新当前内容」后才读到新文稿。缓存仅按 URL 命中，切回应用刷新的是目录。 [AppModel.swift](../../Sources/Tingjian/AppModel.swift) · `observeDevices` / `select` / `reloadOpenContent` | **约 1–2 天。** 打开标签和切回应用时在后台检查当前文件版本，失效后更新正文与关联音频，并保留阅读锚点。先做按需检查，避免启动即监视整棵 iCloud 资料库。 |

| **P3 · 时间戳承诺播放，实际只定位** | 合成 CAF 实测时间戳将播放位置设到 5.0 秒，播放器仍暂停。手动播放推进到约 5.2 秒，切到另一份再回来会恢复到约 5.2 秒并保持暂停。帮助与无障碍标签均写「开始播放」。 [ContentView.swift](../../Sources/Tingjian/ContentView.swift) · `DocumentLineRow` · [AppModel.swift](../../Sources/Tingjian/AppModel.swift) · `seek(toTimecode:)` | **约 0.5 天。** 将标签统一改为「定位到…」，保留播放/暂停状态。若后来选择点击即开播，测试连续点多个时间戳和录音期间的门禁。 |

## 潜在性能与一致性风险

| 优先级与链路 | 证据与用户影响 | 改进、成本与取舍 |
| --- | --- | --- |
| **P2 · 大项目树刷新过宽** | `children(of:)` 为每个直属目录再枚举一层以判断录音标签；切回应用清空整个目录缓存，依序重读根、所有已展开目录和当前目录。选中目录也展开时可能重复读。侧栏拖动对象的计算还会在主线程逐级查目录。隔离本地样本中，500 个子目录各 20 个 Markdown，根枚举首轮约 205 ms，随后约 110–124 ms。大资料库会有更长的树重建窗口，云端占位文件延迟待测。 [ProjectLibrary.swift](../../Sources/TingjianCore/ProjectLibrary.swift) · `children` / `isRecordingBundle` · [AppModel.swift](../../Sources/Tingjian/AppModel.swift) · `reloadLibrary` / `dragUnit` | **约 2–4 天。** 保留上一份目录快照，合并同目录刷新，写操作只更新受影响分支。录音标记延后到需要时或复用已有快照。等真实目录测量后再考虑持久化索引。 |
| **P2 · 长文稿首屏依赖关联音频，部分工作仍在主线程** | 正文读取和段落解析已在后台，时间戳段落使用 `LazyVStack`。首次加载仍在 MainActor 扫全稿找音频引用，并等音轨、时长及播放器就绪后才发布正文。「打开关联音频」另有同步读全文路径；纯 Markdown 和「查看原文」用单个大文本视图。缓存同时持有原文、段落和滚动位置。隔离的 3,000 / 30,000 段纯解析中位数为约 67 / 663 ms（1.07 / 10.65 MB）。 [AppModel.swift](../../Sources/Tingjian/AppModel.swift) · `loadDocument` / `openLinkedAudio` · [ContentView.swift](../../Sources/Tingjian/ContentView.swift) · `DocumentDetail` | **约 2–4 天。** 独立发布正文与音频状态，引用解析并入后台文稿读取，取消被切标签淘汰的任务。先做大小上限和按需过期的缓存评估，普通文本确有长尾后再按段或用 TextKit。基准只测未优化核心模块的内存解析，界面首屏、滚动恢复与峰值内存需另测。 |
| **P2 · 录音和识别的积压缺少边界** | 写盘和送识别分队列，重放环只保留 120 秒，但两个异步队列以及默认策略的识别 `AsyncStream` 可接受更多数据。写盘慢时录音计时会滞后，识别停顿时可能推高内存。采集转换失败存在直接返回的路径。日常模拟运行和历史长测覆盖正常或短故障，长期停顿未实测。 [AudioSource.swift](../../Sources/TingjianCore/AudioSource.swift) · `captureOutput` · [AudioPipeline.swift](../../Sources/TingjianCore/AudioPipeline.swift) · `accept` · [Engine.swift](../../Sources/TingjianCore/Engine.swift) · `start` / `feed` | **约 3–6 天。** 先测队列深度、写盘落后与识别落后；识别超限时从已保存音频追赶或标注缺口，写盘超限及时告警并保住已有音频。避免给两条路径使用同一套丢弃策略。 |
| **P2 · 录音与播放的高频状态扩大刷新范围** | 录音约每秒 10 次更新电平与时长，播放观察者同频更新进度，根视图和文稿行订阅了整个对象。确认文本写日志和每 5 秒写会话状态走 MainActor，录音完成的 Markdown 渲染与写入也在该执行器。拖动滑杆每次变化都发精确 seek。实际掉帧与 CPU 开销待采样。 [ContentView.swift](../../Sources/Tingjian/ContentView.swift) · `ContentView` / `DocumentLineRow` / `playbackControls` · [Recorder.swift](../../Sources/TingjianCore/Recorder.swift) · `tick` / `record` / `finishSession` | **约 3–5 天，建议分步。** 先把进度、电平订阅限制到控制带，拖动时显示预览、松手精确定位。若采样确认 I/O 卡顿，再把有序日志与渲染交给独立执行器，保留退出、错误重试和恢复时的持久化顺序。 |
| **P2 · 改名时可能覆盖外部编辑** | 链接改写预读整个同目录的 Markdown，稍后凭旧快照原子写入，回滚也写旧快照。遇到 Obsidian 或同步进程同时编辑，可能覆盖这段时间内的新内容。前缀批改名逐个递归调用单文件改名，多次读同一组 Markdown。并发写入和回滚故障尚未注入。 [ProjectLibrary.swift](../../Sources/TingjianCore/ProjectLibrary.swift) · `rename` | **约 2–4 天。** 一次生成移动与改链计划，写前检查版本，对可协调的读写使用文件协调，检测冲突即提示重试。普通改名保留同目录作用域，跨目录 Obsidian 引用另行定义。 |
