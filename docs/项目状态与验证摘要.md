## 仍成立的历史修复

P1：

- 会话信息和确认文本写入失败被静默忽略，可能导致异常退出后无法自动发现会话或恢复文字。
- UTF-8 尾行被截断时，恢复逻辑会丢掉此前所有完整事件。
- 等待麦克风权限时没有锁定启动状态，重复点击可覆盖第一份会话的调度对象。

P2：

- 识别收尾超时后仍无限等待 `engine.cancel()`，可能卡住最终音频交付。
- 从待保存的失败会话恢复时，失败状态可能被升级成“完成”。
- 目标目录因重名增加 `_2` 后缀后，纠正逻辑可能按目录名寻找不存在的原稿。
- 重新转写已有结果会覆盖同名文件和用户编辑。
- 识别故障恢复补喂时，首块音频与已确认边界重叠，可能生成重复文字。
- LLM 返回文字中的换行或 Unicode 段落分隔符可绕过段落对应校验。
- 目标目录复制在 `MainActor` 上同步执行，慢目录会阻塞按钮、状态和退出处理。
- 录音期间重复投递退出请求会叠加多个提示；取消后主窗口恢复依赖隐藏标题。

详细修复与逐项验证见 [1.0.1 修复验证](verification/2026-11-13/修复验证_2026-11-13.md)。

## 仍需验证的边界风险

- 48 kHz 转换到 24 kHz 时记录到约 11 ms 的尾部帧差；转换器尾部没有显式冲刷，转换失败也没有完整错误状态。
- 直接输入 Int16 PCM 时缓冲区会被忽略且不置失败标志；默认麦克风通路是 Float32，真实硬件是否触发尚未验证。
- 写入故障时最后缓冲区的保留量仍有少量差异；正常链路和注入故障通过，不等于所有磁盘失败场景都无损。
- 转换队列和识别输入流没有明确的积压上限；30 分钟正常运行未观察到内存持续增长，但不能证明系统语音服务长期停顿时内存有界。
- Swift 5 模式下仍有异步上下文使用 `NSLock` 的警告，尚未通过 Swift 6 严格并发检查。
- 物理拔掉正在使用的输入、睡眠/合盖、耳机热插拔没有实测；当前只覆盖了切换失败、恢复失败、启动失败和迟到回调。
- 侧栏移动/改名/拖放在可见界面没有点完整流程；底层由真实临时目录回归覆盖，仍需人工走一遍。
- 真实课堂术语与中英混合准确率、真实 iCloud 同步仍未验证。
- 真实 Magpie 网关出现间歇性 SDU 401；应用如实显示 HTTP 错误，不自动重试，不能把一次成功当作服务稳定性证明。
