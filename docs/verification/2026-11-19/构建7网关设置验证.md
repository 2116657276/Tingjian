# 构建 7 网关设置验证

2026-11-19。测试版为 `dist/听笺.app`，版本 1.0.1（构建 7），通过严格签名校验。稳定版为构建 6。

## 针对性测试

使用独立测试目录和偏好，通过模拟 HTTP 响应验证应用的网关设置状态。记录见本地 `evidence/gateway-check.log`。

- 旧自定义地址和模型在升级后可用。旧密钥只允许原 API 地址读取，显式默认端口、大小写及完整 Chat Completions 地址可归到同一 API 地址，其他端口使用独立配置。
- 切换网关并刷新后，旧请求迟到的成功响应与 HTTP 401 都无法覆盖当前模型列表或状态。
- DeepSeek 的嵌套档位和兼容网关的平铺档位都可读取。乱序的 `max / low / high` 取 `low`，切换到最低为 `medium` 的模型时使用 `medium`，切回后可读取已缓存档位。
- 隔离模式下，模拟密钥在同一测试会话内可按地址保存、切回和清空。真实网关、真实钥匙串读写与迁移、桌面交互待用户手动验收。

## 用户手动验收

从工程根目录启动隔离版。音频由本机语音合成生成，保存目录和设置按本次测试目录隔离。

```sh
tingjian_trial="$(mktemp -d /tmp/tingjian-gateway-manual.XXXXXX)"
say -o "$tingjian_trial/sample.aiff" "听笺网关设置验证。"
TINGJIAN_TEST_ROOT="$tingjian_trial" TINGJIAN_TEST_AUDIO="$tingjian_trial/sample.aiff" \
  "dist/听笺.app/Contents/MacOS/Tingjian"
```

1. 在「设置 → 文字纠正」依次切换三个网关，确认模型列表只在点「刷新模型」后更新。刷新期间切换到另一个网关，确认状态属于当前网关。
2. 在需要凭据的网关填入测试密钥并点「保存密钥」。切换地址再切回，确认密钥按地址记住。隔离版把密钥保存在当前进程内。
3. 刷新实际网关的可用模型，选择支持多档的模型，核对「自动」显示最低档。可用隔离文稿验证纠正输出。系统钥匙串的持久化和旧密钥迁移需在正常模式下单独验收。
