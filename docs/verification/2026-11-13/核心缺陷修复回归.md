## 接口与交互变化

- `SessionStore.save/append/closeEvents` 现在可能抛错；新增 `prepare/rewriteEvents`，用于首次准备和故障后的完整恢复。
- `loadEvents` 返回 `EventLoadResult(events, issues)`，调用方需要显式处理损坏情况。
- `Recorder.Phase` 新增 `starting`，并提供 `cancelStarting`；退出应用时不会让尚未完成的授权请求启动采集。
- `Recorder.deliveredFiles` 提供真实目录、音频和 Markdown 地址；`persistenceIssue` 提供本地恢复数据保存异常说明。
- 20 秒限制针对识别收尾，不限制慢磁盘的转换和复制耗时；服务不响应取消时，应用仍结束保存，系统服务的释放可延后。
- 仅修改现有状态与按钮可用性：准备时显示未开始采集；文本保存异常明确显示，不能继续显示所有内容正常保存。

## 短时验证

先用修复前二进制执行新增回归，重复开始、UTF-8 截断及覆盖重转写三项失败，证明测试能捕获原问题。首次修复后回归中，中断提示文字与旧断言不匹配、同一路径的 URL 表示不同导致两项失败，已分别修正文案及路径比较。该轮最终原始终端记录未归档；现存 `evidence/suite.log` 是更早的 75 项运行。

最终完整命令：

```sh
. scripts/env.sh
swift build --disable-sandbox --scratch-path /tmp/tingjian-fix-build --product tingjian-check
TINGJIAN_CHECK_ROOT=/tmp/tingjian-fix-green2-20261113 NSUnbufferedIO=YES /tmp/tingjian-fix-build/debug/tingjian-check --real --magpie
```

结果：112 项检查通过，退出码 0（该轮原始终端记录未归档）。`TINGJIAN_CHECK_ROOT` 显式控制套件根目录，避免 macOS 临时目录接口忽略 TMPDIR。复现时请使用新的专用临时目录；工具会将同名测试夹移入废纸篓。原有检查和新增故障回归都在源码内，维护入口为 `Sources/tingjian-check`。

Magpie 使用本机网关、DS SDU、high，仅发送合成文字。实际校正版另存检查通过，原稿保持不变；不据此声称专业术语纠正一定准确。

另外后台编译实际 AppModel 源码，使用专用测试设置、文件音源及合成转写文字，制造交付目录后缀 `_2` 后执行真实 Magpie 纠正。实际原稿保持不变，校正版时间戳对应，未创建窗口或访问钥匙串；该轮日志未归档。

实际音频写入故障另外通过仅对子进程设置文件大小上限验证，记录见 `evidence/recorder-write-limit.log`。不填满真实磁盘，不修改系统全局限制。
