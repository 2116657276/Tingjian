## 一、本轮改动与测试体系优化范围

1. **顶栏与标签栏两行拆分及边线/交互重构**（`Sources/Tingjian/ContentView.swift`、`Sources/Tingjian/TingjianApp.swift`）：
   - 将原单行混装顶栏拆分为第 1 行固定 `contextHeader`（`paper` 背景、高 40pt、底部 1pt `hairline`，左侧展示当前上下文图标与标题，选中非根目录文件时以次级色显示 `父目录 /` 且保图标与 `/` 不被窄窗裁切，右侧固定刷新与 `…` 菜单）与第 2 行独立全宽 `tabBar`（仅 `openTabs` 非空时显示，`windowSurface` 背景、底部 1pt `hairline`）；
   - 横幅各自携带底部 1pt `hairline`，消除悬空灰块、36pt 死区、双底边线与切目录时的水平跳动；
   - `tabBar` 使用 `ScrollView(.horizontal, showsIndicators: false)` + `.scrollIndicators(.never)`，右侧提供无状态 `chevron.down` 溢出标签下拉菜单（0 `@State` 宏），标签整块左侧（图标 + 文字）可点，自动滚动遵守 `accessibilityReduceMotion`；
   - 菜单栏「上一个标签页」「下一个标签页」在无标签时置灰。
2. **纯算法层标签命名消歧与死标签自动清理**（`Sources/TingjianCore/WorkspaceState.swift`、`Sources/Tingjian/AppModel+Library.swift`）：
   - 新增 `WorkspaceTabPolicy` 纯算法模块：覆盖同目录多时间戳+多扩展名、同目录+跨目录并存、父目录显示名/同分钟冲突消歧与去重；
   - `activateTab`、`closeTab`、`closeOtherTabs`、`closeTabsToRight`、`activateRelativeTab` 统一接入死标签自动清理与回退逻辑，检测文件存在时排除同名目录（`!isDirectory`），并将 `audioPositions[dead] = nil` 置于 `select(_:)` 之后防进度写回复活。
3. **测试体系优化**（`Sources/tingjian-check/main.swift`、`Sources/tingjian-check/WorkspaceStateRegression.swift`）：
   - 新增 `--workspace-state-only` 专项快速回归入口（0.02s 跑完 33 项工作区路径映射、高亮定位、标签消歧与死标签状态迁移断言）；
   - 离线全量套件较 Build 32（291 项）净增 23 项断言至 314 项（`--real` 由 299 项增至 322 项）。

### P3 观察与测试事故

- **P3：620pt 缩窗后当前标签可能只露出一条边。** 打开 8–10 个标签、选中最后一个标签后再把宽度从 748pt 缩到 620pt，tabBar 保留旧滚动偏移，当前标签只在最右侧露出一小条；重新从溢出菜单选择后才完整滚入视野。无数据损失或阻塞，属轻微视觉/交互瑕疵。
- **P3：滚到末端时最左侧可能只剩一个孤立关闭「×」。** 多标签 tabBar 滚动到末端时，被裁切的最左标签可能只显示关闭按钮，没有图标和标题，视觉上像孤立控件；功能正常。
- **T4 提示呈现观察：** 状态栏首层显示「1 个问题」，完整的「文件已移动或不存在」文案在状态详情弹层中；功能与文案均存在，但不是首层直显。

- **清理与仓库：** 两个测试 PID 均已退出；隔离根目录、精确匹配的测试 suite plist 与 `/tmp/tingjian-codex-b33-current-root` 指针均已 `trash`；验收执行期间未改源码、脚本或 Git 状态，验收前后代码 diff 摘要一致（测试完成后仅按用户要求更新验证/状态文档）。

## 五、日常使用判断

**结论：可以开始日常使用，建议作为个人课堂录音与转写的主用稳定版；但这不等于全场景验证完成。**

- **支持日常使用的依据**：桌面 GUI 的 T1–T5 共 17 个检查项全部 PASS；顶栏/标签栏两行拆分、Legacy 多标签溢出、溢出菜单、重名消歧、死标签清理及 Build 32 四项高频交互均已在隔离环境实测。自动化侧仍保持离线 314/314、`--real` 322/322 全通过，未发现 P0–P2 应用缺陷。
- **剩余风险集中在真实硬件与真实课堂**：开合盖内置麦拦截、真实麦克风弱音、45–90 分钟长时资源、睡眠唤醒与 iCloud 同步尚未真机验证；这些项目会直接影响“课堂唯一记录方案”的可靠性。
- **建议**：先按[课堂验收清单](../../guides/课堂验收清单.md)做 5 分钟真机硬件预检，再用一节 45–90 分钟课程观察首字延迟、漏识、长时内存/发热与交付完整性；重要课堂同时保留系统录音或原始音频备份。两项 P3 与提示层级观察仅影响视觉/提示细节，不构成日常使用阻断，可留到后续构建收口。
